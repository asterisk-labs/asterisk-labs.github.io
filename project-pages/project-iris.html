The IRIS annotation view: paint a few pixels, let the model fill in the rest, correct, repeat.

IRIS is a web tool for labelling satellite imagery pixel by pixel. It was first built at ESA's Φ-lab in 2019 to speed up the annotation of cloudy Sentinel-2 scenes, and it has since become a popular tool that has been used for a range of other tasks. The user paints a few pixels of each class, a gradient boosted model is trained on those pixels and predicts the rest of the image, and the user corrects the prediction and trains again.

Where we started

The original IRIS, built for the Sentinel-2 cloud mask catalogue, explained in a few minutes.

Why it needs to change

The model is retrained from scratch for every image, which keeps labelling errors from spreading between images but also means that nothing learnt on one image helps with the next. That design made sense when supervised training of a convolutional model was the only reason to build a labelled dataset. It makes less sense now that pre-computed embeddings are available for the whole planet. A linear model on AlphaEarth or TESSERA embeddings can separate many land cover classes with a handful of examples, and the goal of an annotation project is then not a dataset for training a new model but a mapping from classes to regions of embedding space that can be applied anywhere.

What we are building

Over six months, with the support of ESA's Φ-lab, we are extending IRIS along four lines.

Embeddings workflows

Pixel-wise embeddings are added as an image source, with a linear classifier alongside the existing gradient boosted trees, and with annotations shared across the dataset so that a new image arrives with a prediction already drawn. Image-level embeddings from models such as THOR and TerraMind are used to choose which image to annotate next, by looking for the one least like those already labelled, and to decide which images are similar enough to share annotations at all. Language-aligned embeddings, where a class is described by a sentence and the embedding model turns it into a first guess at the mask, are the least certain part of the plan.

Agentic setup

Building a dataset is still the slowest part of starting a project. We are adding a catalogue of data sources and an assistant that turns a description of the task, the region and the data you want into a ready IRIS project, with views and classes chosen to suit the job. Setting up by hand stays exactly as it is.

Time-series annotation

Many questions are about change rather than a single date. IRIS will step through the dates available for a place and keep a mask for each, so annual embedding products and seasonal imagery can be labelled over time rather than one scene at a time.

Visualisation and speed

Embedding products carry 64 or 128 bands and hyperspectral sensors many more. We are reworking how IRIS stores, loads and displays imagery so that views over many bands are quick to make and quick to draw, with cloud-native formats that let the browser read only what it needs.

The people who use it

IRIS has been downloaded and forked many times, but as an open source project with a permissive licence we have little idea what it has been used for or what its users would change. We will be conducting a user survey and setting up a forum where development can be discussed. From that group we will pick two champion use cases, build their datasets with them whilst the new features are being written, and release both datasets at the end of the project. The results and the tool will be presented at a webinar in early 2027.

Anyone who has used IRIS and would like to be involved is welcome to get in touch.
